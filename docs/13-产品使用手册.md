## 1. 使用前提与适用场景

### 1.1 MAT 是什么

MAT 在你**本机的 Android 真机**（或 iOS 模拟器/真机，见 §1.3）上执行 UI 自动化测试。它有三个入口，操作的是**同一份数据**（同一份 `cases/` 用例、同一份 `artifacts/` 产物）：

| 入口      | 命令            | 适合                 |
| ------- | ------------- | ------------------ |
| 命令行 CLI | `mat <命令>`    | 快速执行、批量、接入 CI      |
| 本地配置台   | `mat console` | 日常可视化操作、看图写用例、复核草稿；**工具所有功能和配置均可在本地配置台操作** |
| 测试报告    | 自动生成的 HTML    | 查看每步证据、定位失败原因      |

**核心特点**：被测 App 的安装包、截图与日志**默认不出本机**（本地执行全程不联网，详见 §4.14）；本地执行、自愈、报告全部不限量。

### 1.2 适用场景

| 场景          | 说明                                              | 推荐入口                       |
| ----------- | ----------------------------------------------- | -------------------------- |
| **回归测试**    | 把稳定用例存成套件，每次发版跑一遍                               | CLI / 配置台「用例」页             |
| **冒烟测试**    | 3~10 条核心链路，几分钟出结果                               | 配置台「用例」页一键执行               |
| **探索找 Bug** | 让 AI 自主遍历 App，发现崩溃/白屏                           | `mat explore` / 配置台「探索测试」页 |
| **存量用例迁移**  | 把 Excel/CSV/Markdown 里的手工用例转成可执行用例              | `mat import` / 配置台「用例」页导入  |
| **CI 集成**   | 在 Jenkins/GitLab/GitHub Actions 里跑，产出 JUnit XML | `mat run --junit-xml`      |

### 1.3 明确不适用（当前版本的边界）

- **iOS**：支持**模拟器**与**真机（beta）**。
  - **证书有效期**：`mat ios-setup` 会显示「剩 N 天（MM-DD HH:MM 到期）」，≤3 天转警告、过期转失败。
    免费个人证书 **7 天**到期，到期后真机跑测直接失败。
    续期 = **重新签名一次**（Apple 没有单独的续期接口）：先试 `mat ios-setup --renew`；
    它需要 `xcodebuild` 能用账号，用不了（常见）就回 Xcode 里按一次 **⌘U**。
    注意：证书**还有效时重签不会延长期限**（Apple 只在必要时签发新 profile），所以 `--renew`
    在有效期没变时会**如实报"没有变化"**，不会假装续期成功。
  - 真机跑测：`mat run <用例> --platform ios --serial <udid>`（**USB** 连接）。首次需一次性准备：
    Xcode 登录 Apple ID → 设备上「设置 → 通用 → VPN 与设备管理」信任开发证书 →
    在 Xcode 里对 `WebDriverAgentRunner` 按一次 **⌘U**（生成签名产物）。
    之后 `mat ios-setup` 可**自动起 WDA**（复用已签名产物，不必每次按 ⌘U）。
    **跑登录类用例前还要关掉自动填充**：「设置 → 密码 → 密码选项 → 关闭『自动填充密码』」——
    否则聚焦密码框时会弹「输入 iPhone 密码查看已存密码」，它需要锁屏密码，自动化无法通过。
    准备情况用 `mat ios-setup` 逐项体检（Xcode / 账号 / 团队 / 证书有效期 / 设备 /
    WDA / 已签名产物 / 失败证据源）。
  - **限制（引用本文必须一并说）**：仅 **USB**（不支持 Wi-Fi）；执行期间必须解锁，且
    「设置 → 显示与亮度 → 自动锁定」设为**永不**（有锁屏密码时 WDA 无法代你解锁）；
    免费证书 **7 天过期**，过期需重新 ⌘U；真机**不支持录屏**（`--record` 会明确提示不可用）；
    页面图谱命令（`mat index` / `mat explore` / `mat arrival`）在 iOS 上明确拦截。
  - **实测口径（2026-10-20，iPhone 17 Pro / iOS 26.5.2）**：`cases/ios-demo/` 15 条 ×3 遍 =
    **45/45 通过（100%）、0 条不稳**，69 步全过，约 6.3 分钟/轮（每用例冷启动）。
    lean dump 中位 **383ms**。限制：单机型、单 App（自建靶场），不是真实 App 的结论。
- **云真机大规模并发**：当前是「本地设备优先」，多设备并行与云真机在后续版本。
- **纯 Web / H5 / 小程序**：只面向原生 Android App（含 WebView 内容可通过坐标/视觉兜底处理，但不保证）。
- **多人协作与权限管理**：当前是单机工具，无账号体系与共享用例库。

### 1.4 环境前提

| 项          | 要求                           | 怎么确认                     |
| ---------- | ---------------------------- | ------------------------ |
| 操作系统       | macOS / Windows / Linux      | —                        |
| Python     | **≥ 3.11**（推荐 3.12）          | `python3 --version`      |
| adb        | 已安装并加入 PATH                  | `adb version`            |
| Android 真机 | 1 台，已开启 USB 调试（**iOS 用户可跳过**） | 见 §2 步骤 3                |
| AI 能力（可选）  | 任意 **OpenAI 兼容**模型的 API Key（在中国大陆提供服务需已完成备案） | 见 §3.2；**不配也能用本地执行全部功能** |

> **一键自检**：装好后执行 `mat doctor`，它会逐项检查以上前提并给出可行动的修复提示。
>
> **iOS 用户**：Android 真机非必需。模拟器：本机 Xcode 模拟器 + WDA 跑在 `localhost:8100`；
> 真机：USB 连接后先跑 `mat ios-setup` 逐项体检（首次需一次性准备，见 §1.3），
> 然后 `mat run <用例> --platform ios --serial <udid>`。

## 2. 安装与首次上手（约 10 分钟）

> 以下命令中的 `mat` 是品牌命令；如未生效，等价写法是 `python -m insta_engine`。

### 步骤 0 · 安装

```bash
# Windows（推荐）：pip 直装，装完直接有 `mat` 命令
py -m pip install --user mat-uitest

# macOS / Linux（推荐）：uv 安装，自动解决 Python 3.11+（不需要预装）
curl -LsSf https://astral.sh/uv/install.sh | sh   # 已有 uv 跳过这行
uv tool install mat-uitest
uv tool update-shell                              # 把 ~/.local/bin 加进 PATH，之后重开终端才能直接用 mat

# 已装 pipx（等价备选；内网下载 uv 托管 Python 受限时用这条）
pipx install mat-uitest && pipx ensurepath   # 没有 pipx：brew install pipx（macOS）/ sudo apt install pipx（Ubuntu·Debian）

# 备选（任何平台，不想装 uv / pipx）：venv + pip
python3.12 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install mat-uitest

# 开发者（从源码仓库安装）
# pip install -e ./engine
```

> **为什么按平台分流**：macOS / Linux 上「裸 `pip install`」会被 PEP 668 直接拒绝——Homebrew 装的
> Python 与 Debian 12+ / Ubuntu 23.04+ 的系统 Python 都标记为「外部托管（externally-managed）」，
> `pip install --user` 同样被拦。uv / pipx 自己建独立环境，不受影响；Windows 没有这条限制、pip 是现成的，
> 所以直装最省事。**不要写 `--break-system-packages`**——那是拿用户环境换方便。
>
> 安装位置：uv / pipx 把 `mat` 放在 `~/.local/bin/mat`，pip 直装（Windows）放在
> `%APPDATA%\Python\Python3x\Scripts`；如终端找不到命令，跑一次 `uv tool update-shell`
> （或 `pipx ensurepath`）并重开终端。任何情况下都可用等价写法 `python -m insta_engine`
> （Windows 可写 `py -m insta_engine`）。

### 步骤 1 · 环境自检

```bash
mat doctor
```

逐项输出 ✅ / ❌，未通过的项会附修复建议。**前 4 项（Python / adb / 设备 / 驱动）是关键项**，全部通过才算「就绪」。

### 步骤 2 · 初始化工作区

```bash
mat init
```

在当前目录创建 `cases/`、`artifacts/` 两个目录，并生成一条示例用例 `cases/example-settings.json`（启动系统设置）。

> **重要**：`cases/` 和 `artifacts/` 生成在**你执行 `mat init` 时所在的目录**。之后所有命令都应在这个目录（工作区根）执行，否则会找不到用例文件。

### 步骤 3 · 连接设备

1. 手机：设置 → 关于手机 → 连续点击「版本号」7 次，打开开发者选项；
2. 开发者选项 → 打开 **USB 调试**；
3. 用**数据线**（非纯充电线）连接电脑，手机上弹窗点「允许」；
4. 确认：

```bash
mat devices
# 输出示例：
# ELE-AL00	ELE-AL00	device
```

> 若列不出设备，见 [§5 设备类问题](#51-设备类)。
>
> **iOS**：跳过本节——模拟器确认 WDA 跑在 `localhost:8100`；真机先跑 `mat ios-setup`
> 确认六项全绿，然后 `mat run <用例> --platform ios --serial <udid>`。

### 步骤 4 · 执行第一条用例

```bash
mat run cases/example-settings.json
```

终端会输出：结果、步骤成功率、耗时、失败分类、报告路径。

### 步骤 5 · 查看报告

打开终端打印的报告路径（通常是 `artifacts/example-settings/report.html`）。报告是**本地 HTML**：每一步一行，含状态徽章、失败分类、耗时、**截图证据**，失败步骤附 logcat 链接。

> 报告通过**相对路径**引用 `screenshots/` 目录，整包移动没问题，但请勿把 `report.html` 单独移出所在目录。

## 3. 核心操作流程

MAT 支持五条主线，按你的实际情况选一条即可。

### 3.1 方式 A：手写/编辑用例 → 执行

适合逻辑清晰、定位稳定的核心用例。

```bash
# 1) 新建/编辑用例文件（放在 cases/ 下）
# 2) 执行
mat run cases/my-case.json
```

也可以在配置台「用例」页可视化编辑：左侧选用例 → 右侧「步骤卡」视图逐条编辑 → 保存（保存前自动做格式校验）→ 点「执行」。

**写用例时不知道控件 id？** 配置台「**用例管理/执行**」页 → 打开用例编辑器 → 定位字段是**下拉选择器**：候选来自该包的**页面图谱控件清单**（`res-id` 优先，可按页面/文案搜索），选中即填入 target。清单里没有的允许手填，保存时会提示「`res-id` 不在控件清单」（只提醒、不阻断）。

> 候选来自图谱 ⇒ **先对目标 App 跑一次 `mat index <包名>`**（§4.5），否则下拉是空的、只能手填。

### 3.2 方式 B：一句话生成用例（gen）

适合快速起草，**生成结果必须人工校对后再执行**。

**一次性配置（AI 能力）**：在**你运行 `mat` 命令的目录**创建 `.env` 文件（已被 gitignore。CLI 按**当前目录**加载 `.env`——放在别的目录会静默不生效，这是"端点未配置"最常见的原因；配置台与 MCP 另有工作区解析规则）：

```bash
cat > .env <<'EOF'
GEN_BASE_URL=<你的 OpenAI 兼容端点>     # 如 DashScope / 智谱 / DeepSeek / OpenAI 的 compatible 端点
GEN_API_KEY=你的Key
GEN_MODEL=<语言模型名>
GEN_VL_MODEL=<视觉模型名>      # 可选：视觉兜底，不配则该能力关闭
EOF
```

可按命令单独覆盖模型：`GEN_MODEL_DESCRIBE=<低成本模型>`（高体量、只需忠实还原）、`GEN_MODEL_DIAGNOSE=<强推理模型>`（低体量、需推理），未设回落 `GEN_MODEL`。

两个模型变量分工不同，**不能只配 VL**：`GEN_MODEL` 是生成类命令（gen / convert / describe / diagnose）的**主模型**——发送的是页面控件文本；`GEN_VL_MODEL` 只服务**视觉兜底**（定位失败后发截图重定位，默认关闭、需显式授权）。只配 VL 不配主模型 ⇒ AI 生成不可用。

> 并把 prompt 模板复制为生效文件（`.example` 不生效）：
>
> ```bash
> cp prompts/gen.prompt.example prompts/gen.prompt
> cp prompts/convert.prompt.example prompts/convert.prompt
> ```

> **官方代理（零配置试用，可选）**：不想自己配 API Key 时，用官方轻云服务跑通效果——`.env` 只需三行：把 `GEN_BASE_URL` 指向轻云地址、`GEN_API_KEY` 换成轻云签发的 **token**（不是模型厂商的 Key），并加 `GEN_PROMPT_MODE=server`。此时**无需 `GEN_MODEL`**（prompt 由服务端组装）。代价是控件文本会经我们转给模型厂商（开启视觉兜底时截图也转），要"内容不出本机"请用上面的自带 API Key 方式。
>
> ```bash
> cat > .env <<'EOF'
> GEN_BASE_URL=https://你的轻云地址
> GEN_API_KEY=轻云签发的token
> GEN_PROMPT_MODE=server
> EOF
> ```

**生成与执行**：

```bash
mat gen "输入账号 alice 密码 pass1234，点击登录按钮，验证欢迎文案包含 alice" \
  --package com.insta.demo -o cases/login-gen.json

# 可选：真机试跑校准（生成后自动跑一遍，失败回喂修正，≤3 轮）
mat gen "打开系统设置" --package com.android.settings \
  -o cases/settings-gen.json --calibrate

# 校对生成结果后再执行
mat run cases/login-gen.json
```

**配额**：体验模式**每月 60 次**（官方代理；自带 API Key 不占额度）；`--calibrate` 的试跑**不另计费**。查看余量：`mat status`。

### 3.3 方式 C：导入手工用例（import）

适合把存量 Excel/CSV/Markdown 用例迁移进来。

```bash
mat import 回归用例.xlsx --package com.insta.demo --limit 5
mat import 回归用例.xlsx --package com.insta.demo --no-expand-preconditions  # 关掉前置条件展开
```

- 支持 **Excel / CSV / Markdown / XMind / 文本粘贴**（禅道/TAPD 导出在后续版本）；
- 表头自动启发式映射（标题/步骤/预期/数据/优先级/模块…）；复杂表头可写映射模板 `--template map.json`；
- **前置条件会被自动置备**：像「已进入搜索结果页」这类**可置备的页面状态**，会展开成一段导航步骤插到
  `launch` 之后（每步带 `【前置展开】` 前缀，便于人工复核）。展开会多用一次生成额度/条，
  不想用就加 `--no-expand-preconditions`；
- 产物是**草稿**，按闸门判定分三级（**三级都会写出草稿**——草稿本来就是给人改的）：
  - **A**：闸门没发现结构性问题，建议直接试跑；
  - **B**：有需要人看一眼的警告（如「前置条件需人工确认路径」），改完再跑；
  - **C**：有**必失败**的结构性缺陷（如断言缺定位、断言与导航耦合），**必须改**才能跑；
- 每条问题都带**规则编号**（`[R2]`、`[R6]`…），批次末尾会打印「无阻断缺陷率」与「按规则命中」分布——
  ⚠️ 那是**离线口径**（闸门能判定的缺陷），**不等于**「不改就能跑绿的比例」；
- 配额：**0.5 条/用例**（前置条件展开再 +0.5/条）；批次报告在 `artifacts/imports/<批次id>/import.json`。

**典型路径**：`--limit 5` 小批试跑 → 确认转换质量 → 全量导入 → 配置台逐条复核 → 批量接入回归。

### 3.4 方式 D：探索测试（explore）

让 AI 在预算内自主遍历 App，发现**崩溃 / 白屏 / 黑屏 / 异常**。

```bash
mat explore com.example.app --minutes 2 --steps 30 --max-depth 3
```

| 参数            | 含义             | 默认 |
| ------------- | -------------- | -- |
| `--minutes`   | 时长预算（分钟）       | 2  |
| `--steps`     | 步数预算           | 30 |
| `--max-depth` | 页面层级上限（L0 首页起） | 3  |
| `--serial`    | 指定设备（多台在线时用）   | 唯一在线设备 |
| `--platform`  | 设备平台：android（默认）或 ios（模拟器 / 真机） | android |

- **时长与步数双上限**：到点即停；
- **安全**：支付/结算/客服/订单/退出登录等**敏感控件自动跳过**；
- **层级**：L0 = 首页，每点击一次下钻一层；达到 `--max-depth` 后不再下钻，改为回退（把预算留给浅层页面）；
- **离场保护**：点击跳到第三方 App 会自动回退，不污染被测 App 的页面层级；
- **越探越深（增量）**：探索结果会**合并进页面图谱** `artifacts/page_index/<包名>.json`。下次探索会读回已点过的分支并**跳过**它们，预算更多花在新分支上。  
  输出里给两个数：「读回 N 个已试分支」是读回量，「其中本轮真正跳过 M 个」才是实际省下的；M 明显小于 N 时程序会主动提示（说明这一轮没认出旧页面）；
- 发现项附**截图与复现路径**（如 `L0 首页 → 点[外卖] → L1 → 点[订单] → L2`）。

配置台「探索测试」页是等价的可视化入口。

### 3.5 方式 E：本地配置台（console）

日常推荐入口，可视化操作。

```bash
mat console            # 打开 http://127.0.0.1:7420（仅本机监听）
mat console --port 7421   # 端口被占用时换一个
mat console --share    # 局域网分享：打印内网链接 + 一个访问口令，同事首次打开输一次
```

## 4. 关键功能说明

### 4.1 用例结构（DSL）

用例是 JSON，字段用 camelCase。

```jsonc
{
  "caseId": "case_t1",                       // 全工作区唯一
  "name": "demo 登录",
  "target": { "package": "com.insta.demo" }, // 被测 App 包名
  "vars": { "账号": "alice", "密码": "pass1234" },
  "steps": [
    { "id": "s1", "intent": "启动应用", "action": "launch",
      "params": { "package": "com.insta.demo" } },

    { "id": "s2", "intent": "输入账号", "action": "input",
      "target": { "strategy": "res-id", "value": "com.insta.demo:id/username",
                  "fallback": { "strategy": "text", "value": "账号" } },
      "params": { "text": "${账号}" } },

    { "id": "s3", "intent": "点击登录并验证", "action": "tap",
      "target": { "strategy": "res-id", "value": "com.insta.demo:id/login_btn" },
      "onFailure": "heal",
      "assertions": [
        { "type": "text-contains",
          "target": { "strategy": "res-id", "value": "com.insta.demo:id/welcome_text" },
          "expected": "alice" }
      ] }
  ]
}
```

**动作 `action`**：`launch` · `tap` · `long-press` · `input` · `clear` · `swipe` · `scroll` · `back` · `home` · `key-event` · `wait`

**定位策略 `target.strategy`**（可选值，越靠前越稳定）：`res-id` · `text` · `textContains` · `description` · `xpath` · `image-template` · `vision-llm` · `point`

**断言 `assertions[].type`**：`exists` · `not-exists` · `text-equals` · `text-contains` · `enabled` · `disabled` · `checked` · `selected`（后四个为**控件状态断言**，读控件树状态；`point` 坐标定位不支持，会如实判失败）

**失败处理 `onFailure`**：`abort`（默认，终止）· `retry`（整步重试一次）· `heal`（触发自愈 + 视觉兜底）

### 4.2 定位策略链、自愈与视觉兜底

一次定位失败时，引擎会**逐级兜底**，越靠后成本越高（**注意：`text` 定位本身自带「精确→描述→包含」等价链，文案微调由它解决，不消耗自愈额度**）。**先跑过 `mat index` 的话，第一级「图谱自愈」能免费处理「控件 id 改名」**——这是最常见的改版形式：

```
res-id → text（等价链：text 精确 → desc 精确 → text 包含 → desc 包含）
       → 用例内 fallback → xpath → point
       → image-template（需可选依赖）→ vision-llm（视觉大模型）→ 失败
```

- **自愈（heal）**：当步骤声明 `"onFailure": "heal"` 时，本地模糊重定位 + 视觉兜底命中后，会记录一条**自愈提案**（不自动改写你的用例）。
  ```bash
  mat heal list artifacts/case_t1        # 查看某次执行的自愈提案
  mat heal apply cases/case_t1.json --run artifacts/case_t1
  # 产出 cases/case_t1-healed.json（不覆盖原用例），真机复核后自行替换
  ```
- **视觉兜底（vision-llm）**：配置 `GEN_VL_MODEL` 后启用。把失败截图 + 步骤意图发给视觉模型，返回坐标执行。**红线**：模型置信度 < 0.7 或 `found=false` 时**拒绝执行**，不做盲点。
- **成本**：视觉兜底走**官方代理**时体验模式 **20 次/月**（自带 API Key 不限，token 由你的服务商计费）；**同屏缓存命中不计费**（同一屏重复重试零成本）。

### 4.3 失败五分类

每次失败自动归因，报告里以徽章展示，帮你快速分流：

| 分类                     | 含义                              | 典型处理                          |
| ---------------------- | ------------------------------- | ----------------------------- |
| `app-crash`（产品 bug·崩溃） | logcat 检出 FATAL EXCEPTION / ANR | 提 Bug 给开发                     |
| `env-failure`（环境问题）    | 设备离线、锁屏、adb/连接类错误               | 解锁重连后重试                       |
| `assert-fail`（断言失败）    | 断言未通过                           | 检查用例预期是否正确                    |
| `locate-fail`（定位失败）    | 找不到目标控件                         | 换 res-id / 配 fallback / 开视觉兜底 |
| `unknown`（待归因）         | 以上都不匹配                          | 看报告截图与 logcat 人工判断            |

### 4.4 测试报告读法

| 产物     | 路径                                     | 内容                             |
| ------ | -------------------------------------- | ------------------------------ |
| 单用例报告  | `artifacts/<用例名>/report.html`          | 每步状态、失败分类、截图、logcat            |
| 套件聚合报告 | `artifacts/<套件名>/index.html`           | 各用例结果汇总 + 各自报告链接               |
| 数据驱动聚合 | `artifacts/<用例名>/index.html`           | 按数据组聚合                         |
| 探索报告   | `artifacts/explore/<批次id>/report.html` | 深度分布、发现列表（含复现路径）、访问页面          |
| 原始数据   | `artifacts/<用例名>/run.json`             | 用例快照 + 逐步证据索引（配置台/自愈/趋势的统一数据源） |
| 执行历史   | `~/.mat/history.jsonl`                 | 每次执行的摘要追加                      |

报告还会展示**性能数据**：`launch` 动作经 `am start -W` 记录**启动耗时**，用例结束采样被测包 **TOTAL PSS 内存**。

### 4.5 页面图谱（防幻觉 + 探索沉淀）

让 AI 生成用例时只引用**真实存在**的控件，从源头降低「编造控件 id」的概率。

```bash
mat index com.example.app              # 真机轻量爬取（默认 30 步 / 15 页）
mat index com.example.app --refresh --steps 50
```


- 爬取前自动唤醒/解锁/跳过开屏广告；**支付/结算/客服等敏感控件在爬取期不可点击**；
- 落盘 `artifacts/page_index/<包名>.json`（图谱 schema v2）；
- 之后 `mat gen` / `mat import` 会**自动注入控件清单**，AI 只能引用真实 res-id；
- 定位失败时，报告的警告区自动附「当前页面可见控件」，人工修用例不再盲猜。

**图谱会随探索自动生长**（不需要你手动维护）：

| 沉淀字段                                     | 来源    | 作用                                           |
| ---------------------------------------- | ----- | -------------------------------------------- |
| `depth` / `parent_key` / `parent_action` | 探索    | 页面层级与复现路径；执行期判断「该步是否属于此页」                    |
| `tried`                                  | 探索    | 已点过的分支 → 下次探索跳过（按页面信号包含度认页；输出里区分「读回」与「真正跳过」） |
| `alt_entries`                            | 探索    | 同一页的**其它入口**（一页多入口）                          |
| `edges`                                  | 探索    | **完整跳转图**（含次数）→ 覆盖率、备选到达路径                   |
| `structure`                              | 索引/探索 | **零 AI** 抽出的页面结构：分区（顶部/中部/底部）、关键元素、动态区域      |
| `step_health`                            | 探索    | 到达动作的成功/失败计数 → 入口文案变了能看出来                    |
| `app_version`                            | 设备    | 版本变了页面结构大概率变，用于判断图谱是否该重采                     |

以上全部**不花 AI 额度**。唯一花钱的是可选的一步——给页面起中文名与写功能描述：

```bash
mat describe com.example.app            # 一次调用描述整批（缺省=全部剩余页），计 1 次生成额度
mat describe com.example.app --limit 20  # 只先描述 20 页（仍是 1 次额度）
mat describe com.example.app --refresh  # 重算已有描述（人工标题不会被覆盖）
```

- 跑完后报告的页面表显示中文名（AI 生成的会带「（AI）」后缀）；
- 不跑也完全可用——报告会退回显示 Activity 短名 + 关键元素；
- 图谱本身不依赖它，`mat gen` / `mat explore` 都不会自动触发它。

**AI 起的名字不满意？你可以自己改**（**不花额度**）：

```bash
mat review com.example.app                          # 生成复核页，浏览器里逐页改标题
mat review com.example.app --apply <下载的 JSON>      # 应用（写回图谱）
mat review com.example.app --replay                 # 图谱被重跑覆盖后，用它恢复你的修改
```

- 复核页是**自包含 HTML**（截图内联），每页一行「截图 + 可编辑标题」，带筛选框；
- **你比 AI 更懂你的 App**：AI 常把同一类页按内容词拆成很多名字（一批搜索结果页被叫成  
  「A搜索页」「B搜索页」…），把它们**改成同一个名字**（如统一叫「搜索结果页」）价值最大；
- 改过的标题标为**人工**，此后 `mat describe` **不会覆盖**；
- 你的修改存在 **`review/<包名>.json`**（与图谱**分开**）——图谱是派生物、重跑会重建，  
  而复核结论是你的资产，`--replay` 一条命令就能恢复；
- 页面标识对不上的条目会被**逐条列出来**，不会静默丢弃。

> **也可以在配置台里改**：`mat console` → 左侧「**页面复核**」。  
> 一样是逐页改名（带截图、可筛选、能撤销），保存即写回图谱。  
> CLI 适合批量/脚本化，配置台适合边看边改。

**复核改了名字之后，会影响哪些东西？**（先说结论：**它改的是"页名"，不是"怎么点"**）

| 下游                                    | 受不受影响                           | 说明                                            |
| ------------------------------------- | ------------------------------- | --------------------------------------------- |
| **HTML 报告**里的页面表                      | ✅ 受影响                           | 显示复核后的名字                                      |
| `mat gen` / `mat import` 的**页面结构上下文** | ⚠️ **仅当 `GEN_GRAPH_CONTEXT=1`** | 该注入**默认关闭**（它会改变 AI 的输出，需先做 A/B）；开启后**页名 + 页面用途**会进提示词（用途来自 `mat describe`，未描述过的页只有页名） |
| `mat gen` / `mat import` 的**控件清单**    | ❌ 不受影响                          | 默认注入的是控件清单（res-id + 文案 + Activity），**里面没有页名** |
| **`mat run` 执行用例**                    | ❌ 不受影响                          | 用例里写的是 res-id / 文案，与页名无关                      |
| **执行期自愈**（控件 id 改名）                   | ❌ 不受影响                          | 走图谱里的 `res-id → 文案` 历史映射，不读页名                 |
| **`mat explore` 认页 / 增量跳过**           | ❌ 不受影响                          | 走页面信号（`identities`）匹配；页名只用于显示                 |
| MCP `mat_page_graph`                  | ✅ 受影响                           | 返回的页面清单带 `title` / `title_source`             |

> 换句话说：**复核让「人和 AI 看到的页名」变准，但不改变「点哪个控件、怎么找到它」** ——  
> 后者本来就只依赖控件与页面信号，不依赖名字。**如果你想让复核也影响生成结果，  
> 需要显式开 `GEN_GRAPH_CONTEXT=1`**（并建议先自己做一次对照，看生成质量有没有变好）。

### 4.6 报告校准（失败归类判错了怎么办）

执行报告会给每个失败步骤一个**五分类**（产品 bug 崩溃 / 环境问题 / 断言失败 / 定位失败 / 待归因），  
`mat diagnose` 还会再叠一层 LLM 的四分类归因，**没把握时明确标「建议人工确认」**。  
归因时会自动注入**页面图谱证据**（该 App 跑过 `mat index`/`mat explore` 才有）：失败步骤的
res-id 在图谱里是否存在、历史可见文案是什么、图谱快照时间——「res-id 曾存在而现在定位失败」
是 UI 改版的硬证据，修复建议也会直接给你"改用文案「xx」定位"这种可执行的改法。证据是加分项：
没有图谱时归因照常工作，只是少这张牌。

问题是：**它标了"需要人工"，但此前没有地方让人回答**——报告是只读的，分类在跑的时候一次定死。  
于是一个**判错的分类会一直跟着你**，而且它看起来完全正常。

```bash
mat calibrate artifacts/case_xxx            # 生成校准页，对着证据逐步骤改判
mat calibrate artifacts/case_xxx --apply <下载的 JSON>   # 应用：改报告 + 落成规则
mat calibrate --show-rules                  # 查看累积的规则
```

- 校准页列出每个失败步骤：**规则判定 + LLM 归因（证据/置信度）+ 错误 + logcat 摘录**；
- 改判后报告会**重渲染**，并在分类旁标一个绿色的「人工」——你能看出这条是自己判的还是机器判的；

⚠️ **校准分两层，产出完全不同，别混**：

| 层级                                | 你改的是             | 效果                                 |
| --------------------------------- | ---------------- | ---------------------------------- |
| **① 失败归类**（页面上半部分）                | 报告里这条失败**算什么性质** | 分类正确 ⇒ **避免误提单**；但 ⚠️ **用例仍然是失败的** |
| **② 断言校准**（页面下半部分，抠得到「期望/实际」时才出现） | **用例的断言预期**      | **结果本身变对** ⇒ 下次跑**真的通过**           |

⇒ **只做 ① 不够**：分类只是标签。真正「校准测试结果」（让通过/失败正确）要落到 **②**。  
② 会写 `cases/<名>-calibrated.json`（**不覆盖原用例**，照 `mat heal` 的先例）。

- ⚠️ **关键**：想「下次不再犯」，就在页面上填「**错误里包含**」或「**日志里包含**」——  
  那会落成一条**规则**，以后同类失败**自动**按你的判定归类。**留空则只改这一次**。

**典型场景**：探索撞上风控页 ⇒ 找不到控件 ⇒ 机器判成「断言失败」（像是产品缺陷），  
而真相是「环境问题」。人一眼能看出，机器看不出 ⇒ 校准一次，以后不再误提单。

> ⚠️ 规则**必须带内容条件**（「错误/日志里包含」）。只写「所有断言失败都改成崩溃」  
> 会把**真的**断言失败也一起藏起来，那比不校准更危险 —— 所以这种规则会被拒绝。  
> 规则只改**分类**，不会让失败的步骤变成通过。

`mat index` 与 `mat explore` **写同一份文件**：`index` 建控件清单，`explore` 补层级与分支；  
`mat status` 可查看各包图谱的「页面数 / 跳转边数 / 已描述数」。

> **建议**：对要长期维护的 App，先 `mat index` 一次，再用 AI 生成，质量明显更稳；  
> 常跑 `mat explore` 的 App，图谱会越用越准。

### 4.7 凭据管理

用例里不要写明文密码，用凭据引用。

```bash
mat cred set github_password     # 输入不回显
mat cred list                    # 只列名，不显示值
mat cred del github_password
```

### 4.8 数据驱动

同一套步骤跑多组数据（如多个账号）：

```jsonc
{
  "caseId": "case_login_ds",
  "steps": [ /* ... */ ],
  "datasets": [
    { "name": "alice", "vars": { "账号": "alice", "密码": "pass1234" } },
    { "name": "bob",   "vars": { "账号": "bob",   "密码": "wrong" } }
  ]
}
```

执行时**自动按组跑**，每组独立产物目录与报告，并聚合到 `index.html`。变量优先级：**数据组 > 用例 vars > 凭据**。

**共享数据（多组数据复用）**：数据可以放在工作区 `data/*.json`，用例用 `ref` 引用（`#` 后是锚点键）：

```jsonc
// data/accounts.json → {"vip": {"账号": "vip_user", "密码": "..."}}
"datasets": [
  { "name": "VIP",  "ref": "data/accounts.json#vip" },
  { "name": "临时", "vars": { "账号": "tmp" } }   // 自带 vars 覆盖文件里的同名键
]
```

文件按「用例/套件所在目录 → `<工作区>/data/`」查找；**文件缺失或锚点不存在会直接报错**——不会带着空数据跑到一半才红。

**前置步骤 / 收尾步骤**：需要先置备状态（登录、切到某份数据）时写 `setup`（主步骤前执行；失败 ⇒ 这条用例记「未执行」，**不算失败**）；需要清理时写 `teardown`（主步骤后 best-effort 执行，失败只记录、不改用例状态）：

```jsonc
"setup":    [ { "id": "p1", "action": "input", "target": {"strategy":"text","value":"账号"}, "params": {"value": "${账号}"} } ],
"teardown": [ { "id": "t1", "action": "back" } ]
```

### 4.9 套件与 CI 集成

**套件** = 一个"测试项目"，把相关用例打成一个组一起跑。文件是 `cases/<名称>.suite.json`：

```jsonc
{
  "name": "登录冒烟",
  "cases": [
    "cases/example-settings.json",
    "cases/t1-demo-login.json"
  ]
}
```

**分阶段编排**：需要「先初始化、再跑主流程」时用 `stages`（阶段按书写顺序执行）：

```jsonc
{
  "name": "发版回归",
  "stages": [
    { "name": "setup", "on_failure": "abort", "cases": ["cases/login.json"] },
    { "name": "main",  "on_failure": "abort", "cases": ["cases/search.json", "cases/cart.json"] },
    { "name": "teardown", "cases": ["cases/logout.json"] }
  ]
}
```

- `on_failure: abort`：该阶段出现**真失败**就停（避免初始化挂了还硬跑，后面全变成假红）；`skipped`（前置未置备/未执行）**不触发**中止。默认 `continue`，与原有行为一致。
- 条目可以指向**另一个套件文件**，递归展开（最多 3 层），公共初始化套件可被多个项目复用。
- 聚合报告的用例名带 `[阶段名]` 前缀，产物按阶段分目录。
- ⚠️ 控制台暂只支持平铺 `cases` 套件；分阶段套件请用命令行 `mat run`。

**`mat suite` —— 套件管理**（`mat run` 早就能跑套件，但此前套件只能手写 JSON）：

```bash
mat suite list                              # 列出工作区里的套件
mat suite new smoke --add 'login.json' 'cart.json'   # 新建并带上首批用例
mat suite add smoke '*.json'                # 批量加（支持 glob，自动去重）
mat suite rm  smoke login.json              # 移除某条
mat suite show smoke                        # 详情：顺序即执行顺序 + 每条的包名
mat suite check smoke                       # 校验：文件存在 / DSL 合法 / 包名一致
mat run cases/smoke.suite.json              # 跑（与普通用例同一套执行路径）
```

> `mat suite check` 会拦**跨 App 混跑**——这是套件最常见的手写错误：它不会报错，
> 只会在跑到一半时因为目标不匹配而失败。`cases/*.suite.json` 不会被 `mat run cases/ --app` 误当成用例
> （批量过滤读 `target.package`，套件没有这个键）。

**CI（JUnit XML + 机器可读摘要）**：

```bash
mat run cases/smoke.suite.json --junit-xml result.xml --json
```

- `--junit-xml` 产出可被 Jenkins/GitLab/GitHub Actions 直接消费的 XML；
- `--json` 在末尾追加机器可读摘要；
- **退出码**：`0` 全部通过 / `2` 有失败 / `3` 前置条件拒跑 / `4` 未跑完（setup 失败或中途中止，2026-10-24 起）/ `1` 运行错误（可用于 CI 判定）。

**GitHub Actions 示例**：

```yaml
- run: pip install mat-uitest
- run: mat run cases/smoke.suite.json --junit-xml result.xml
- uses: actions/upload-artifact@v4
  with: { name: mat-report, path: artifacts/ }
```

**按 App 批量执行**（用例目录 + `--app`）：

```bash
mat run cases/ --app com.insta.demo        # 批量跑该 App 的全部用例
mat run cases/my-case.json --app com.insta.demo   # 单用例：校验包名一致（防误跑）
```

#### 3~5 人小组怎么一起用

**用例和套件都是纯 JSON、都在 `cases/` 且不进 `.gitignore` ⇒ 协作靠 git 就够，不需要任何服务端。**

| 要做的事 | 怎么做 |
|---|---|
| 共同维护用例 | 用例仓进 git，改动走 PR review。`git blame` 能查到每条用例是谁改的 |
| 共同维护测试项目 | 用 `mat suite` 维护 `.suite.json`，同样走 PR review |
| 谁跑都能看到结果 | `mat console --share` 局域网分享，**同一 Wi-Fi / VPN 下的同事浏览器直接打开**（报告零出域）。🔴 **多人共用需要团队授权**：标准/体验授权面向单人使用，`--share` 下也只有安装者本人 1 人 |
| 提交前统一验一遍 | CI 上 `mat run <套件> --junit-xml`，PR 上直接看红绿 |
| 各人自己的凭据 | 🔴 **凭据不进 git**：用例里写 `${cred.名称}`，每个人在自己机器上 `mat cred set <名称>` 配一遍 |

**四条必须知道的边界**：

1. 🔴 **设备是物理资源，串行。** 配置台已按设备加锁，多人同时点运行会**排队**而不是互相污染
   （并发跑同一部手机会互抢点击、产出"看着正常、实际无效"的报告且不报错——所以宁可排队）。
   一台机器接一部手机 ⇒ 团队共享设备时总时长不变，只是把等待从"各自跑各自的"变成"排队"。
2. 🔴 **`--share` 要访问口令**（2026-10-12 起）：启动时终端打印一个 6 位口令，同事首次打开链接输一次即可
   （`--password` 可自己指定）。口令只挡「误入」——它仍是**可信内网**工具，拿到口令的人有全部权限
   （含运行与删改用例）。对外暴露请走 CI 而不是 `--share`。
3. 🔴 **一个激活码默认最多 2 台机器**（`mat activate --machines` **查看**已绑机器，`--unbind` 释放名额）。
   团队共用一台机器跑 `--share` 反而只算 1 台；各自装则要解绑旧名额。
4. 🔴 **多人共用同一个控制台需要团队授权**（2026-10-25 起）：`--share` 对标准/体验授权
   只放安装者本人 1 人——第二位同事会拿到「团队共享随团队授权提供」的提示。
   报告是**单文件 HTML**，只想给同事看结果时直接发文件即可，不需要授权。

**当前不支持**（需要平台化，尚未做）：细粒度权限（谁能改/谁只读）、变更审计日志、组织级额度。
多人同时**操作同一个配置台**也不支持——`--share` 是"各自看+各自点运行"，不是在线协同编辑。

### 4.10 结果通知

执行完成后推送到飞书/钉钉/自定义 webhook。

> `.env` 放在**你运行 `mat` 命令的目录**（CLI 按当前目录加载；放错目录 = 静默不生效）。

在 `.env` 配置：

```bash
MAT_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
MAT_NOTIFY_FORMAT=feishu          # feishu | dingtalk | generic
```

**机器人创建的两个坑**（都是实测必踩项）：

- **飞书**：目标群 → 设置 → 群机器人 → 添加 → 自定义机器人。**签名校验保持关闭**——MAT 发的是纯文本消息，不支持加签，开了签名会一直推送失败；
- **钉钉**：目标群 → 设置 → 智能群助手 → 添加 → 自定义（Webhook）。安全设置选**"自定义关键词"**并填 `MAT`——通知内容以 `[MAT]` 开头，正好命中；**不要选"加签"**。

通知是 best-effort：推送失败**不影响**执行主流程。

### 4.11 配额

> 对外名称（2026-10-23 起）：**体验模式** / **标准模式** / **团队模式**（原「体验版 / 标准版 / 团队版」）。
> 改名只动显示名——激活码内部标识仍是 `MAT-pro.*`，代码判据仍是 `plan == "pro"`。
>
> 🔴 **两个独立维度，别压成一维**（2026-10-24 修正）：
> - **使用方式** = 体验模式（未激活）/ 标准模式（激活）/ 团队模式（**团队授权**）
> - **AI 接入** = 官方代理（**有**月度上限）/ 自带 API Key（**不设上限**，本站不计量）
>
> 三种使用方式**都能自带 API Key**；标准模式走官方代理同样是合法组合。
> `mat status` 打印成 `标准模式 · AI 接入: 自带 API Key`，就是在表达这两维。
>
> 🔴 **团队共享只随团队授权提供**（2026-10-25 起）：`mat console --share` 把控制台
> 共享到局域网，但**成员名额只有团队授权才给**——标准/体验授权面向单人使用，
> `--share` 下也只有安装者本人 1 人，第二位同事会看到「团队共享随团队授权提供」的提示。
> （此前是"未激活 2 人、激活后 5 人"，已作废。）

| 能力 | 体验模式 | 标准模式（激活后） |
| --- | --- | --- |
| 本地执行 / 自愈 / 报告 | **不限量** | **不限量** |
| 官方代理 · AI 生成用例 | 60 次/月 | 2,000 次/月 |
| 官方代理 · 手工用例导入转换 | 含在生成额度（按 0.5 条/次计） | 同左 |
| 官方代理 · 视觉兜底 | 20 次/月 | 300 次/月 |
| 自带 API Key 的 AI 调用 | **不设上限**（本站不计量，由你的服务商结算） | **不设上限** |

```bash
mat status                     # 查看生成用量、视觉用量、AI 配置、凭据、设备
mat activate <激活码>           # 需要更高额度时用激活码解锁
mat activate --machines        # 查看本激活码已绑定的机器
mat activate --unbind <机器标识> # 解绑一台机器（换机 / 重装场景）
```

> 体验模式「本地执行全档不限量」是有意设计——本地跑的边际成本≈0，所有本地能力永久免费。
> 需要更高额度时见官网（mobileaitest.com）。
>
> **续费不用你填日期**：官方签发的是一张**时长卡**（码里带「加 N 个月」）。激活时由**服务端**读你本机
> 旧授权、自己算出 base 再 +N 个月，重签一张普通码写盘 —— 所以无论你当前到期日是哪天，都是「从现有到期日往后加」。
> 核销按（码，机器）幂等：**同一张卡重复激活不会重复加时**。
>
> 断网时会按码内的兜底到期日本地激活（谁长用谁），联网后重跑 `mat activate <该卡>` 即可补上核销。
> 激活一张到期日更早的码时，程序会提示「本机已有更长的有效期」并**保留原授权**（不会静默缩短）。

**关于标准模式与机器绑定**（激活后需知）：

- `mat activate` 会**先在本地完成激活**（离线也能用），然后**额外**向官方服务登记一次。
  **登记失败不影响本地使用**，只是暂时拿不到服务端额度；联网后重跑 `mat activate <激活码>` 即可补上。
- 使用**官方代理**时，标准模式的生成额度是 **2,000 次/月**（服务端计量、可查）；体验模式 60 次/月。
  只用自带 API Key（BYOK）时不受服务端计量约束，且控件文本与截图不经我们。
- 一个激活码默认最多绑定 **2 台机器**（留一台余量给换机 / 重装）。超限时本地照旧激活成功，
  但**服务端额度不会开通**，并会提示你解绑；`mat activate --machines` 查看已绑机器。
- 换机 / 重装系统：在**新机器**上 `mat activate --unbind <旧机器的标识>` 即可释放名额，
  那台旧机器之后**可以重新激活**。

### 4.11.1 邀请同事得额度

把邀请码发给同事，**他用起来之后**你会获得额外额度。

```bash
mat invite                                   # 首次会生成你的邀请码，并显示台账
mat invite --accept ABCD-2345                # 同事侧：接受邀请
mat invite --confirm                         # 兜底：自动通知没生效时手动确认
```

| | 你会得到 |
|---|---|
| 你是免费用户 | **服务端生成次数**（每成功邀请一位） |
| 你是标准模式用户 | **标准模式时长**（自动延长有效期，无需手动激活） |

**三条要知道的**：

1. **只有对方跑完一轮才计酬**——装机 ≠ 使用。`mat invite` 的台账里会显示「待生效」，
   表示对方已接受邀请但还没跑通第一轮；那不是出错。
2. **每月有上限**（防止被刷），台账里会显示「本月计酬 x/y」与「超额未计酬」。
3. **首次生成邀请码会向 MAT 官方服务注册一个匿名 ID**：只上传一个公钥哈希，
   不含账号 / 邮箱 / 手机 / 设备标识。**只有这一步需要联网**，其余功能完全不受影响；
   不想用可以不运行 `mat invite`，不运行就不会注册。

> 邀请功能也可以在**本地配置台**（`mat console` → 设置 → 账号）里操作。
> 台账数字来自本地快照，查看它**不会联网**。

### 4.13 AI 编程助手接入（skill / MCP）

让 Claude Code / CodeBuddy / Cursor / Trae / WorkBuddy 这类 AI 编程助手**直接驱动 MAT**。
两条入口都**随包分发**，装完命令就有；按需选一条或两条都接。

**① skill —— 教助手怎么用 MAT**

skill 是一份写给 AI 助手的说明（何时跑用例、何时探索、怎么读结果），装一次即可：

```bash
mat skill install                     # 装到 ~/.claude/skills/（Claude Code / CodeBuddy 系约定）
mat skill install --target workbuddy  # WorkBuddy AI（~/.workbuddy/skills/）
mat skill install --dir <目录>         # 其他助手：显式指定 skill 目录
mat skill path                        # 只看包内位置（想手动复制时用）
```

- **装完要开新会话**才会加载——多数助手在会话启动时读 skill。
- 目标已存在且与你手里那份内容不同时**默认不覆盖**（你可能补过自己的团队约定）；确认要覆盖加 `--force`。
- **助手不能执行终端命令时**（只能用 IDE 的「技能上传」入口）：从 `github.com/vlmpilot/mat-skill` 取 `mobileapp-testing/` 整个目录导入。手动拷的副本**不会自动更新**，MAT 升级后要重拷一次；与包内版本冲突时以包内为准（`mat skill path` 打印的就是包内那份）。

**② MCP —— 让助手常驻调用 MAT 的工具**

```bash
pip install 'mat-uitest[mcp]'         # 必须带 [mcp] extra，否则入口会报「MCP SDK 未安装」
mat mcp --root <工作区>                # 先手动跑一次；看到「MAT MCP 就绪」再往下配
# 等价的 console script：mat-mcp --root <工作区>
```

把下面这段填进助手的 MCP 配置（Cursor / CodeBuddy / Trae 等 `mcpServers` 结构通用）：

```json
{
  "mcpServers": {
    "mat": {
      "type": "stdio",
      "command": "mat",
      "args": ["mcp", "--root", "/path/to/你的工作区"]
    }
  }
}
```

接入后助手可用 11 个工具：`mat_status` / `mat_list_cases` / `mat_get_case` /
`mat_generate_case` / `mat_run_case` / `mat_run_app` / `mat_explore` / `mat_job` /
`mat_cancel_job` / `mat_page_graph` / `mat_controls_context`。

- 各家入口位置不同：**CodeBuddy** 设置 → MCP → Add MCP；**Trae** 设置 → MCP → 手动添加；
  **WorkBuddy** 连接器管理页 → 自定义连接器 → 点「信任」。
- ⚠️ **Trae 的 `command` 不能含空格**——路径带空格时换成不含空格的包装脚本。
- ⚠️ **`command` 必须真的能用**：先照上面手动跑通、看到就绪提示再填进 IDE，否则配了也白配。
- MCP 是 **stdio 长驻进程**，随助手会话生灭——**关掉 IDE 会中止进行中的任务**；
  超长任务用 `mat console` 提交（独立进程，不随会话消亡）。

> **工作区怎么定位**（MCP 与配置台同一套规则）：`--root` 参数 / `MAT_WORKSPACE` 环境变量 >
> 当前目录（含 `cases/` 或 `artifacts/` 才算工作区）> 回退 `~/.mat/workspace`。

### 4.14 数据与隐私

MAT 的设计前提是**测试数据留在你自己机器上**。分情况说清楚（与官网隐私政策同一口径）：

| 动作 | 会离开本机的东西 | 说明 |
| --- | --- | --- |
| 本地执行 / 自愈 / 报告 | **无** | 截图、logcat、页面快照、用例只写工作区或 `~/.mat/`，不联网 |
| AI 生成（`gen` / `describe` / 导入转换 / `diagnose` 归因） | **文字描述 + 控件清单**（不含截图） | 发给你自己配置的模型服务；需先在工作区 `.env` 配好端点与 Key |
| **视觉兜底**（vision-llm） | **当前屏幕截图** | 仅在控件树无法判定时触发；不想要这项能力，不配 AI 即可 |
| `mat activate` | **机器标识（哈希）** | 只发一个由硬件信息派生的哈希，不发任何原始硬件信息；登记失败不影响本地激活 |
| `mat invite` | 邀请码与达成状态 | 用于发放邀请奖励 |
| 控制台新版本检查 | **一次 HTTPS GET（IP + 当前版本号）** | 控制台启动时向 PyPI 查询最新版本号，请求不带任何机器信息；断网/超时静默跳过，`MAT_NO_UPDATE_CHECK=1` 可整体关闭 |

- 报告、用例、截图默认只在本地；`mat console --share` 走**局域网**链接，数据零出域。
- 官网页面本身不含统计脚本与 Cookie（服务器保留常规访问日志）。
- 详细条款见官网 `mobileaitest.com/privacy.html`。

## 5. 常见问题与排查

> 第一步永远是 `mat doctor`——它会指出是哪一类前提没满足。

### 5.1 设备类

| 现象                  | 可能原因                          | 处理                                                       |
| ------------------- | ----------------------------- | -------------------------------------------------------- |
| `mat devices` 列不出设备 | USB 调试未授权 / 线是纯充电线 / adb 服务异常 | 手机上重新授权；换数据线；`adb kill-server && adb devices`            |
| 多台设备时连错或报错          | 默认取唯一在线设备，多台时不确定              | 显式指定：`mat run ... --serial <serial>`                     |
| WiFi 调试连不上          | 未建立连接                         | 先 `adb connect <ip:port>`，再执行命令                          |
| 大量「环境问题」分类          | 设备锁屏 / 执行中被拔插                 | 开发者选项 → 打开「不锁定屏幕」；执行中不要拔插。引擎执行前会**自动唤醒/解锁**（best-effort） |

### 5.2 执行类

| 现象                  | 可能原因               | 处理                                                                           |
| ------------------- | ------------------ | ---------------------------------------------------------------------------- |
| 定位失败（`locate-fail`） | 控件选择器不稳定           | 优先用 `res-id`；给 target 配 `fallback`；或开启视觉兜底（`GEN_VL_MODEL`）。报错信息已含策略链每一级的失败证据 |
| 断言失败（`assert-fail`） | 用例预期写错 / 文案变了      | 看报告截图确认实际界面，修正 `expected`                                                    |
| 报告里图片不显示            | 报告用相对路径引用截图，被单独移动了 | 不要单独移动 `report.html`；或在 `artifacts/xxx` 目录下 `python -m http.server`          |
| 配置台任务一直「进行中」        | 任务超时（如设备锁屏/离线）     | 超过阈值会被看门狗标记超时并给出原因；解锁重连后重试，反复出现则重启配置台                                        |
| 数据驱动只跑了一组           | 用例未声明 `datasets`   | 检查用例是否有 `datasets` 数组；有则会自动按组执行                                              |
| 中文输入失败              | 输入法/编码问题           | 视觉命中的输入框走「点击聚焦 + 快速输入」；Windows 终端乱码执行 `chcp 65001`                           |

### 5.3 AI 能力类

| 现象                    | 可能原因                    | 处理                                                                                                 |
| --------------------- | ----------------------- | -------------------------------------------------------------------------------------------------- |
| `mat gen` 报缺环境变量      | `.env` 未配置或未生效          | 在**工作区根目录**建 `.env`，写 `GEN_BASE_URL/GEN_API_KEY/GEN_MODEL`（用轻云模式时只写前两项 + `GEN_PROMPT_MODE=server`） |
| `mat gen` 报 prompt 缺失 | prompt 模板未复制为生效文件       | `cp prompts/gen.prompt.example prompts/gen.prompt`（`convert` 同理）。**轻云模式无需此步**                      |
| `mat gen` 报「额度不足」     | 本月免费额度用尽（轻云模式）          | 等次月自动重置，或用激活码解锁更高额度；本地执行不受影响，也可切回自带 API Key 的 local 模式                                                        |
| 生成的用例定位不到控件           | 未建页面索引，AI 凭经验编造控件       | 先 `mat index <包名>` 再生成（自动防幻觉）                                                                      |
| 视觉兜底不生效               | `GEN_VL_MODEL` 未配置      | 在 `.env` 加 `GEN_VL_MODEL=<视觉模型名>`，`mat status` 可确认状态                                         |
| 视觉兜底提示额度不足            | 官方代理额度（体验模式 20 次/月）用尽 | 等下月重置；此时步骤会**优雅降级**为普通定位失败，不影响本地执行；自带 API Key 不受此额度限制 |
| 生成额度用尽                | 体验模式 60 次/月用尽             | 同上；本地执行、自愈、报告不受影响                                                                                  |

### 5.4 平台类

| 现象             | 处理                                               |
| -------------- | ------------------------------------------------ |
| Windows 终端中文乱码 | 执行 `chcp 65001` 后重试                              |
| 找不到用例文件        | 确认命令在**执行过 `mat init` 的目录**下运行（`cases/` 在那里）     |
| 配置台端口被占用       | `mat console --port 7421` 换端口                    |
| 不想自动弹浏览器       | 加 `--no-open` 启动，再手动访问 `http://127.0.0.1:7420`（端口被占用时以 `--port` 为准） |

## 6. 注意事项与最佳实践

### 6.1 设备稳定性（影响成功率的第一因素）

- 执行前**保持屏幕常亮**（开发者选项 → 不锁定屏幕），避免锁屏导致大量环境问题；
- 执行中**不要拔插数据线**、不要手动操作手机；
- 固定用同一台设备做回归，减少机型差异带来的抖动；
- 需要冷启动的场景，在用例首步用 `launch` + `"cold": true`，确保从已知初始态开始。

### 6.2 定位策略选择（决定用例寿命）

- **能用 `res-id` 就用 `res-id`**：最稳定，不受文案改动影响；
- 没有 res-id 时用 `text` / `description`，并**配 `fallback`** 提高鲁棒性；
- 尽量避免 `xpath` 和 `point`（坐标/结构一变就失效）；
- 关键路径的步骤开 `"onFailure": "heal"`，让自愈与视觉兜底兜住偶发失败；
- 定期 `mat heal list` 看提案，把稳定的自愈结果 `heal apply` 回写，让用例越跑越稳。

### 6.3 用例组织

- 一条用例聚焦**一条链路**，不要塞成巨型用例（失败定位更难）；
- 按 App 包名分组（`target.package`），目录批量执行用 `mat run cases/ --app <包名>`；
- 用例 `caseId` 保持全工作区唯一；
- 用**套件**组织回归集（如 `smoke.json` 冒烟、`regression.json` 全量）；
- 复用数据用 `datasets`，复用密码用 `cred`，不要在用例里写死。

### 6.4 节省 AI 配额

- **先 `mat index` 再 `gen`**：索引注入控件清单，一次生成可用率更高，少返工；
- 生成后**人工校对**再执行，避免反复重新生成；
- 用 `--calibrate` 让真机试跑自动修正（试跑不另计费）；
- 批量导入先用 `--limit 5` 小批验证转换质量，再全量。

### 6.5 数据安全与合规

- 被测 App 安装包与截图**默认不出本机**；纯本地模式下报告只存本机；
- 密码等敏感信息用 `mat cred` 管理，用例中以 `${cred.名称}` 引用，报告与日志不回显；
- 需要迁移/备份或行使数据可携带权时用 `mat export`；
- 配置台仅监听 `127.0.0.1`，不对外开放。

### 6.6 CI 集成建议

- 用 `--junit-xml` 产出标准 XML，配合 CI 的测试报告视图；
- 用**退出码**判定构建成败（`0` 通过 / `2` 有失败 / `3` 拒跑 / `4` 未跑完 / `1` 错误）；
- CI 机器上注意：需自备 Android 设备或用支持真机的 CI runner，并确保 `adb` 可用；
- 把 `artifacts/` 作为构建产物上传，保留截图证据链；
- 配 `MAT_WEBHOOK_URL` 让失败结果直接推到群里。

### 6.7 GitHub Actions 接入（PR 门禁）

前提：一台插着 Android 测试机的 **self-hosted runner**（labels 含 `android`）。  
完整可抄模板见仓库 `examples/ci/mat-pr.yml`；最小配置：

```yaml
- uses: vlmpilot/mat@main
  id: mat
  with:
    package: com.example.shop
```

环境抖动注明不计入产品失败）。分类标签与建议归因与本地报告同源。

## 附录 C：demo-app 靶场（自建对抗集）
