> 只讲对外可验证的结构与约束；具体实现参数、迭代过程中的取舍论证属研发过程记录，不随源码公开。

---

## 1. 分层与依赖

```
入口层    __main__.py（子命令）      web_server.py（本地 HTTP API）     web/（无构建单页）
                    ↓                            ↓
编排层    runner.py（步骤流水线）  explore.py（自主遍历）  page_index.py（页面爬取）  suite.py
                    ↓
能力层    locator.py（策略链+自愈）  vision.py（视觉兜底）  ai_client.py（NL 生成）  manual_import.py（导入）
                    ↓
驱动层    driver.py（UiAutomator2 封装）  device.py（adb 设备发现）  perf.py（启动/内存）
                    ↓
模型/状态 dsl.py（DSL 模型，单一真相源）  quota.py  credentials.py  report.py
```

分层有一条硬约束：**上层可以依赖下层，下层不反向依赖上层**。

`Runner` 只要求驱动对象实现 `dump() / screenshot() / click()` 等少量方法，视觉客户端与凭据
存储同样可注入。因此测试可以用 `FakeDriver` 跑通整条执行路径——这是「无设备也能测」成立的原因。

## 2. 模块职责

| 模块 | 职责 |
|---|---|
| `dsl.py` | DSL 数据模型（Step / Locator / Assertion / TestCase），三源归一的数据核心 |
| `driver.py` | UiAutomator2 薄封装（延迟导入，Android） |
| `locator.py` | 定位策略链降级 + 本地模糊自愈 + 图像模板匹配 |
| `runner.py` | 步骤流水线：等待策略、动作执行、断言评估、自愈调度、证据留痕、失败分类 |
| `vision.py` | 视觉大模型兜底定位（坐标契约 + 置信度门禁） |
| `ai_client.py` | 自然语言 → DSL 生成，含真机 dry-run 校准回路 |
| `manual_import.py` | 手工用例四格式解析 + 启发式列映射 + 分级降级 |
| `page_index.py` | 真机页面爬取 → 控件清单 → 注入生成上下文（防幻觉） |
| `explore.py` | 规则驱动自主探索 + 崩溃 / 白屏黑屏发现 |
| `report.py` | 单文件 HTML 报告 / 套件聚合页 / JUnit XML |
| `web_server.py` | 本地配置台 HTTP API + 任务看门狗 |
| `quota.py` / `credentials.py` | 配额滚动 / 凭据本地存储（0600） |
| `perf.py` | `am start -W` 启动耗时 + `dumpsys meminfo` |
| `heals.py` | 自愈提案收集与回写（只提议，不覆盖原用例） |

## 3. 设计原则

这几条决定了代码的形状，读源码前先知道它们会省很多时间：

1. **DSL 是唯一的数据核心**。自然语言生成、手工导入、录制都收敛到同一个 `TestCase` 模型，
   且同时接受 camelCase 与 snake_case。这让「编辑 / 迁移 / 自愈」能互通。

2. **依赖倒置做彻底**。核心流程只依赖驱动对象的少量方法，视觉客户端与凭据存储都可注入 ⇒
   测试用假驱动即可跑通全流程，无需真机。

3. **fail-safe 默认值**。步骤结果默认按失败计（未完成不等于通过）；失败分类遇到未知特征
   归入 `unknown` 而不是 `passed`。宁可误报，不可漏报。

4. **能确定性判定的，不调模型**。等待、定位降级、失败分类都以可解释的规则为先，
   模型只用在规则确实做不到的地方。成本更低，且每条结论可复核。

5. **自愈默认只提议**。回写时生成新文件、不覆盖原用例，并保留审计说明——风险最高的功能
   用最保守的策略。

6. **导入路径永不整批失败**。单条用例的格式瑕疵只降级处理，不中断整批转换。

7. **open-core 边界靠代码结构实现，不靠注释声明**。生成用的 prompt 外置为文件（不进本仓库），
   AI 客户端的密钥读取隔离在一处，视觉能力有显式开关。

8. **把踩过的坑写成回归测试**。这是本项目希望长期保持的习惯。

## 4. 边界与适用范围

- **平台**：Android 真机与模拟器为主支持；iOS 为**模拟器 + 真机（beta，2026-10-18 起）**
  （`mat run --platform ios [--serial <udid>]`，驱动层 `wda_driver.py`，真机走 usbmux）。
  页面图谱相关命令（`index` / `explore` / `arrival`）在 iOS 上仍明确拦截。
  真机限制（引用须一并说）：仅 USB、须保持解锁（自动锁定设为「永不」）、免费证书 7 天过期、
  不支持录屏；实测 15 条靶场用例 ×3 遍 = **45/45 通过**（单机型、单 App，靶场非真实 App）。
- **网络**：执行、报告、控件层自愈、探索测试全程离线可用；只有 AI 生成与视觉兜底需要联网。
- **数据**：被测 App 包、截图、日志默认不出本机；AI 生成路径只发送文字描述与控件清单，
  不发送截图。
- **可靠性定位**：自愈目前是「本地模糊匹配」一档，视觉兜底是「最后手段」；两者都按
  提案 / 兜底处理，不会静默改变你的用例。
- **已知结构性取舍**：步骤流水线集中在一个较大模块中（等待、执行、断言、自愈、留痕、分类
  同处一个文件），接口以鸭子类型为主、暂无显式协议层。这是「先跑通再分层」的阶段性结果。
