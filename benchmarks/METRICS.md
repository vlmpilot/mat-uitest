# 评测指标定义

> **定义公开、数据内部**：这里写清每个指标怎么算，任何人可以按同一口径复现自己的数字；
> 项目的真实跑测数据不随源码发布。两者不冲突——**没有定义的数字才是不可复核的**。

## 口径纪律（先于指标）

以下五条不满足，指标数字一律不可比：

1. **数字只从 `run.json` 读**：不接受手填、不接受从截图目测（`scripts/bench_ledger.py` 的纪律）。
2. **`skipped` 不进分母**：可选步骤（开屏广告、权限弹窗）被跳过是语义正确，不是失败。
3. **风控页单列，不算失败**：被验证码/滑块拦住的运行记 `blocked`，排除出分母。
4. **数字自带指纹**：报告必须带引擎版本、被测 App 的版本与 APK sha256、设备型号。
   少了任一项，这个数字下次就不知道在跟什么比。
5. **小样本给区间**：n < 30 时同时给 95% 置信区间（Wilson），只报点估计会误导。

## 七个指标

### 1. 一次通过率（first-pass rate）

- **分子**：首次运行即 `passed` 的任务数
- **分母**：参与运行的任务数（剔除 blocked / env_error）
- **回答**：生成或手写的用例，有多少能一次跑通
- **已实现**：`mat eval` 的 `overall.median`（按步骤成功率取三遍中位）
- ⚠️ 单独看它会被"把用例写松"刷高——必须和假绿率、强断言覆盖率一起看

### 2. pass^k（稳定性）

- **定义**：同一任务连续 k 次（默认 k=3）全部通过，才算"稳定通过"
- **分子**：k 次全过的任务数；**分母**：任务数
- **回答**：这条用例明天还能过吗
- **已实现**：`per_task` 三态（N/N 通过、0/N 稳定失败、0<p<N 不稳）+ `unstable` / `stable_fail`

### 3. 假绿率（false-green rate）

- **标注前提**：任务集里标了 `expect: fail` 的任务（已知有缺陷，**应失败**）
- **分子**：标注 `expect: fail` 却 `passed` 的运行次数
- **分母**：标注 `expect: fail` 的有效运行次数
- **回答**：绿灯里有多少是"没测出来"而不是"真没问题"
- **已实现**：`mat eval` 的 `overall.false_green = {labelled, passed, rate, tasks}`
- ⚠️ 无标注时 `rate = null`，**不要读成 0**

### 4. 强断言覆盖率（strong-assertion coverage）

- **定义**：带 `strong` 层断言的步骤 / 总步骤
- **strong 层**：`not-exists` / `text`（等于或包含）/ `selected` / `enabled` / `disabled`
  （以 `dsl.AssertionType` 的 8 种为准）；`exists` 分 `skeleton` / `tautology` 另计
- **回答**：为什么假绿会发生——断言只证明了"页面到了"，没证明"结果对了"
- **已实现**：`assertion_strength.py` 五层分类；**未接入** `mat eval` 汇总（待办）

### 5. 自愈率（heal recovery rate，G7）

- **分子**：触发自愈（步骤带 `heal` 记录）且该步最终 `passed` 的次数
- **分母**：触发自愈的步骤数
- **回答**：定位失败时，兜底救回来的比例
- **已实现**：`overall.heal = {triggered, recovered, rate}`
- ⚠️ "兜底成功但动作失败"不算恢复

### 6. 误愈率（false-heal rate）

- **分子**：标注 `expect: fail` 却 `passed`，且至少一步是靠自愈救回的运行次数
- **分母**：标注 `expect: fail` 的有效运行次数
- **回答**：自愈有没有**把真 bug 当成控件变化放过去**——自愈工具最致命的失败方式
- **已实现**：`overall.false_heal = {count, rate, tasks}`
- 与假绿率的关系：误愈率 ⊆ 假绿率；两者差值是"用例本身太弱"造成的假绿

### 7. grounding 命中率（定位准确率）

- **定义**：视觉定位返回的坐标落在人工标注真值框内的比例
- **分桶**：按屏幕区域（顶部 / 中部 / 底部导航）与目标类型（文字 / 图标 / 自绘）分开报
- **回答**：换模型、换 prompt 到底有没有用（榜单分数不能直接用）
- **未实现**：需要公开截图 + bbox 标注集（`benchmarks/grounding/`，待建）

## 怎么用这些数字

- **只看一次通过率 = 朝错误方向优化**：把断言写松，这个数立刻变好。
- **假绿率 + 强断言覆盖率是一对**：前者说"错了多少"，后者说"为什么会错"。
- **误愈率必须和自愈率一起报**：只报"救回多少"会系统性高估自愈的价值。
